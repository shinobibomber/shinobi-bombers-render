# V3 Guild, Chat and Codex audit

Audited 1 November 2026. This report is read-only analysis of the current implementation; no gameplay, database, account or financial data was changed.

## References inspected

Read the user's pasted implementation request; Design 12 master and all nine dedicated Guild prompts; Designs 15 and 16 prompts and READMEs; Codex content schema. Inspected Guild Home original art, nine-screen overview, Chat reference and Codex reference. Read the Guild prototype as source data without executing it. Its sample records, prices, bonuses, rankings, timers and modal feedback are illustrative and must not ship as live data.

Current source is `releases/current-render-repository/shinobi-bombers-render-2b5bc22c0d844faae3e0086548a79da87370bf1d`, not the historical root `source/` build. `app/` is generated by the verified archive plus ordered apply helpers. Any implementation must be included in this build pipeline, not only edited in generated files.

## Feasible safe implementation order

1. Build a responsive shared Guild shell with all nine submenus and an honest no-guild state; add real navigation to Guild and Chat and reuse the global header/Chest. Do not import the prototype's fake state or baked data panels.
2. Implement a small persistent, non-economic Guild core if needed: create/discover, apply, officer approval/rejection, membership list, leave/kick, roles, notice and general settings. Use atomic server transactions, audit events and optimistic versions. No fee, guild XP, stat bonus or “capacity 50” should be assumed from art; any capacity must be an explicitly documented operational configuration.
3. Add real authenticated Global and Guild chat first, with cursor history, idempotent send, server timestamps, rate limits, plain text rendering, read cursors, report/block and membership checks on every query/send. Same-origin bounded polling is compatible with the current JSON API; label it accurately rather than claiming websocket delivery. SSE/WebSocket requires a deliberately implemented authenticated transport, reconnection and per-room reauthorization.
4. Keep Team/DM/official event feeds/attachments unavailable until their services exist. Do not display fabricated unread badges, online names, announcements or staff availability.
5. Implement all eight Codex categories now from current selectors/config, search and FAQ, with valid navigation links and no accidental financial actions. This is low risk and does not require invented backend records.
6. Guild Battle, shared Guild Boss, Missions, Shop and Tech should show carefully designed locked/unavailable states with their dependency explanation. Do not substitute the local solo Boss Hunt for a shared guild raid.

## Proposed additive schema/API contracts

These are implementation recommendations, not existing tables or approval to add economic rules. Every table uses existing `scope` isolation and wallet identity. Migration is additive/idempotent; rollback disables the new endpoints/UI first and preserves social records. Never drop economic tables.

- Guild core: `guilds(scope,id,name,tag,description,notice,leader_wallet,version,created_at)`, `guild_members(scope,guild_id,wallet,role,joined_at)` with unique `(scope,wallet)`, `guild_applications(scope,guild_id,wallet,state,message,created_at,decided_at)` and auditable `guild_events`. Index membership, application state and event cursor.
- Actions: `guild-state`, `guild-discover`, `guild-create`, `guild-apply`, `guild-decide`, `guild-role`, `guild-kick`, `guild-leave`, `guild-settings`, `guild-events`. Each mutation validates strings, membership and role hierarchy on server; lock guild row before last-slot admission; deduplicate by request ID; reject stale versions. Leader transfer/dissolution need explicit confirmation and defined semantics.
- Chat: `chat_messages(scope,id,conversation_id,sender_wallet,body,created_at,client_nonce)` unique `(scope,sender_wallet,client_nonce)`; a monotonic server cursor; `chat_reads`; `chat_blocks`; `chat_reports`; indexes `(scope,conversation_id,id)`. Guild channel IDs are resolved from server membership, never blindly trusted client room names. Users cannot submit `type=system`/staff badges.
- Actions: `chat-capabilities`, `chat-history`, `chat-send`, `chat-read`, `chat-block`, `chat-report`; all authenticated. Allowlist Global/Trade and own Guild as capabilities become available. Request history returns bounded pages and a next cursor. Hold wallet/rate lock for duplicate-send/rate check and insert. A retry with same nonce and changed body fails. Server filters blocked authors, forbids unauthorized private rooms, and invalidates access after leave/kick.
- Profile/presence: only if needed, validated `social_profiles` with unique approved display names and a deliberately minimal public presence representation. Current session tokens never enter public response records. Reuse authoritative server time and TTL.

## Decisions that would change economics or mechanics

Do not implement Guild creation/join fees, donations, points exchange, shop stock/prices, Ryo/EXP/stat boosts, research costs, raid rewards, Guild mission rewards, matchmaking entry fees or leaderboard payouts from screenshots. Their amounts, funding, eligibility, accounting and limits have no current authoritative configuration and need separate economic/mechanical specification. Non-economic social persistence and read-only Codex do not require a new currency.

## Required tests for implementation

- Two authenticated wallets; unauthenticated access rejects; cross-scope isolation; nonmember guild read/send rejects; leave/kick revokes access.
- Concurrent last-slot accepts and role hierarchy; duplicate mutation/request ID; stale settings version; safe leader leave/transfer; no unauthorized changes.
- Duplicate/changed-nonce chat send, rate/repeated-message throttle, server ordering/cursor pagination, plain text XSS, forged system identity, block/report checks, reconnect/account switch and listener cleanup.
- Empty true data states rather than prototype examples; real TTL presence count only; mobile navigation/touch/keyboard/reduced motion.
- Codex all8categories, search/filter/FAQ, displayed numeric values match current sources, internal links valid, Chest opens and returns to same screen, no transaction triggered from knowledge content.
- Existing ownership/transaction idempotency and game regression suites remain green; no changes to balances, odds, rewards or core combat from social UI.

No tests of new social functionality were run because this task was an audit and those systems do not exist yet. Report should not be presented as a completed Guild/Chat implementation.
